# 12 — QA

What to run, when, and what "pass" looks like. §1 runs on every change; the
rest run on a real iPhone before every TestFlight build that goes to App
Review. Record results in the sign-off table (§7) — a row without a result is
a fail.

## 1. Automated checks (every change)

**Web (repository root)**

```sh
npx tsc --noEmit
npm run lint
npx vitest run
npm run build
```

**Database** — `05-backend.md` §3 (psql against `supabase start`, or
`run-without-docker.mjs`). Pass: `mobile_test.sql: all assertions passed`,
`rls_test.sql: passed`.

**Edge Functions**

```sh
cd supabase/functions
deno check iap-confirm/index.ts app-store-notifications/index.ts delete-account/index.ts
deno test --allow-env --allow-net _tests/functions_test.ts      # 17 passed | 0 failed
```

**App**

```sh
cd mobile
npm run typecheck
npm run lint
npm test                      # unit tests for src/lib (entry checks, doctor summary)
npm run bundle:check && rm -rf dist
npx expo-doctor
```

**Gates** (from `mobile/`; each must print nothing)

```sh
grep -rn "ROUTE STUB\|not built yet" src                    # no unfinished screens (App Review 2.1)
grep -rn "console\.\(log\|warn\|info\|debug\)" src          # no logging of data
grep -rniE "service_role|sk_live|sk_test|BEGIN PRIVATE KEY" . --exclude-dir=node_modules
grep -rn "YOUR_DOMAIN" src                                  # release builds only
```

## 2. Against the deployed backend

Run after every `supabase db push` or `functions deploy`.

```sh
# function is up and requires a session → 401
curl -s -o /dev/null -w "%{http_code}\n" -X POST https://YOUR_PROJECT_REF.supabase.co/functions/v1/iap-confirm
# webhook is public and rejects garbage → 400
curl -s -o /dev/null -w "%{http_code}\n" -X POST -H "content-type: application/json" -d '{}' \
  https://YOUR_PROJECT_REF.supabase.co/functions/v1/app-store-notifications
# the anonymous key cannot read data → []  (or a permission error)
curl -s "https://YOUR_PROJECT_REF.supabase.co/rest/v1/test_results?select=id&limit=1" \
  -H "apikey: $EXPO_PUBLIC_SUPABASE_PUBLISHABLE_KEY"
supabase secrets list                                        # every name in 05-backend.md §6
```

In the SQL editor:

```sql
-- every public table has RLS on → no rows
select c.relname from pg_class c join pg_namespace n on n.oid = c.relnamespace
where n.nspname = 'public' and c.relkind = 'r' and not c.relrowsecurity;
```

## 3. Sandbox purchase matrix

Setup: a development or TestFlight build; two sandbox Apple Accounts (S1, S2)
from `07-payments.md` §3; two bbiom accounts (U1, U2) signed up with email
codes. The device's sandbox account (Settings › Developer › Sandbox Apple
Account) is S1 unless a row says otherwise. Sandbox subscriptions renew every
few minutes (a month is about 5 minutes).

To see what the server recorded:

```sql
select app_store_status, app_store_product_id, app_store_expires_at,
       app_store_auto_renew, app_store_environment
from subscriptions where user_id = '<U1 id>';
select notification_type, subtype, received_at from app_store_notifications
order by received_at desc limit 5;
```

| # | Do | Expect |
| --- | --- | --- |
| 1 | U1, Free. Paywall → monthly → confirm | Sheet closes; Settings shows Pro with a renewal date within seconds. Row: `active`, monthly id, `Sandbox`. A `SUBSCRIBED` notification is in the ledger. **This row proves keys, secrets, product ids and the notification URL.** |
| 2 | U1 on the website, Settings → try to subscribe | Shows Pro; checkout refused with the "bought in the iPhone app" sentence |
| 3 | Delete the app, reinstall, sign in as U1, paywall → Restore | Pro; the restore notice. No second purchase |
| 4 | Sign out, sign in as U2 (same S1), paywall → Restore | "already belongs to a different bbiom account"; U2 stays Free; U1's row unchanged |
| 5 | U1: Settings → Manage subscription → switch to yearly | Apple's sheet; after the change, the row's product id becomes the yearly id |
| 6 | U1: Manage subscription → cancel | Settings says "Ends {date}"; row `app_store_auto_renew = false`. After expiry: Free, every test still readable, adding a 21st test is refused with the limit sentence |
| 7 | Leave an active subscription for two renewals | `app_store_expires_at` moves forward each time; `DID_RENEW` in the ledger |
| 8 | Turn on airplane mode after confirming in Apple's sheet, before the app reports back | "We could not confirm the purchase yet. You have not lost it: we will keep trying."; turn the network on and relaunch → Pro without any action |
| 9 | Billing failure: for S1 turn off renewals where iOS offers it (Settings › Developer › Sandbox Apple Account › Manage), wait for renewal | `billing_retry` (or `grace` if a grace period is enabled) — Free in retry, Pro in grace |
| 10 | An account that is Pro through Stripe opens the paywall | "You are on Pro through the bbiom website"; no purchase buttons |
| 11 | Paywall on a slow connection | "Loading plans…", then prices from the App Store in the local currency; the buy button is disabled until they arrive |

Refunds and revocations cannot be triggered from a sandbox app; they are
covered by the function tests (`REFUND` → `revoked` → Free).

## 4. Manual test script

Run on a phone, with a stopwatch for the timed rows. These are the three jobs
from `01-product.md`; the targets are its success measures.

**First run**
- [ ] Install → sign in with Apple → first profile → Overview's empty state. Under 1 minute.
- [ ] Sign out; sign in with an email code; sign out; sign in with Google. Each lands on the same account when the email matches.

**Capture** (`02-ux.md` §6)
- [ ] From install to a saved first test: under 5 minutes.
- [ ] A 20-marker report (Comprehensive Metabolic + Lipid Panel + one single marker), typed with "Next" only: about 3 minutes.
- [ ] Type `2,4` → saved as 2.4.
- [ ] LDL `2.4` in mg/dL → the "Double-check" sheet offers mmol/L (= 93 mg/dL); **Use mmol/L** fixes the row.
- [ ] A clearly extreme but real value → **The value is correct** saves it.
- [ ] Same marker on the same date as an existing result → duplicate warning once.
- [ ] A date in the future cannot be picked.
- [ ] Keyboard bar: **Next** walks every value field in order; **Done** closes the keyboard; the Save button stays visible above the keyboard.
- [ ] A "range on report" entered in mmol/L is shown converted on the marker.
- [ ] Swipe down a sheet with typed values → "Discard this test?"
- [ ] Airplane mode → Save → "Not saved…"; form unchanged; network on → Save works.
- [ ] Free account with 20 tests → 21st → the limit sentence and one offer of Pro.

**Recall**
- [ ] Locked phone, airplane mode → open app → a named marker's chart: under 10 seconds.
- [ ] Markers: search "a1c", "LDL", "tsh" each find the marker; scopes switch; body-system card on Overview opens Markers at that section.
- [ ] Marker detail: drag across the chart → reading block follows with a haptic per point; release → latest.
- [ ] Unit switch on glucose → value and history change everywhere; persists after relaunch and on the website.
- [ ] Marker detail: press and hold a history row → Delete → the point leaves the chart and the Timeline. With VoiceOver, the same via the row's Actions rotor.

**Reassure**
- [ ] Overview leads with "N of M in range"; only out-of-range and borderline markers appear as cards; each has its shape and word.
- [ ] A custom range set on a marker changes its status; clearing it restores the catalog range.
- [ ] Profile with "Prefer not to say" on a sex-specific marker shows the note.

**Timeline, profiles, summary**
- [ ] Timeline groups by year, newest test open, life event added and removed, a test deleted after confirmation.
- [ ] Free: second profile refused with the plan sentence. Pro: six profiles; switching updates every tab.
- [ ] Custom marker created, given a result, then removed → archived (results kept).
- [ ] Settings › Doctor summary on Free shows the Pro tag and opens the paywall.
- [ ] Doctor summary (Pro): window control; flagged first; Share → PDF opens in the share sheet; Print works; the PDF contains the disclaimer. Free → paywall.

**Your data**
- [ ] Export CSV and JSON → open each in Files; every result present.
- [ ] Settings › About: the three pages open.
- [ ] Delete account (Apple user) → Apple sheet → account gone; signing in again with Apple creates an empty account; in the database no rows remain for the old user id. With an active App Store subscription the "One more step" alert appears.

## 5. Accessibility

- [ ] Settings › Accessibility › Display & Text Size › Larger Text at the largest non-accessibility size: Overview, Markers, marker detail, Add results and paywall have no clipped or overlapping text.
- [ ] VoiceOver: sign in, add a test, open a marker and hear its history, buy (sandbox) — all possible without sight. Marker rows read as one element ("LDL Cholesterol, 94 mg/dL, borderline").
- [ ] Settings › Accessibility › Display › Color Filters › Grayscale: every status still distinguishable by shape and word.
- [ ] Reduce Motion on: nothing essential is lost.
- [ ] Every tappable thing is at least 44×44 pt (Accessibility Inspector in Xcode, or by thumb).

## 6. Offline and privacy

- [ ] Airplane mode: Overview, Markers, a marker, Timeline all render from cache; writes say they need a connection and keep the input.
- [ ] App switcher shows the cover, not results.
- [ ] Require Face ID on → background 61 s → Face ID asked; cancel → stays locked with an Unlock button; under 60 s → no prompt.
- [ ] Sign out → sign in as another account → nothing of the first account appears, even in airplane mode.
- [ ] (Mac) Make an encrypted Finder backup, inspect it with any backup browser: no `bbiom-query-cache.json`.
